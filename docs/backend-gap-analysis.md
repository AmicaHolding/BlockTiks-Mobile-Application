# Sahra Backend · Spec-vs-Implementation Gap Report

Generated by audit agent, 2026-11-18. Read alongside `designs/handoff/02-api.md`
and `03-rules.md`. Citations are `file:line` in `backend/`.

**Architecture summary:** Fastify + single-table DynamoDB (`pk`/`sk` + `gsi1`/`gsi2`, `scripts/table.ts:27-39`). The implementation is a **single-user-role MVP** (`User.role ∈ FAN|CREATOR|ADMIN`, `db.ts:87`), the entire Organisation/Membership model, ledger, credential versioning, holds, transfers-as-claims, and offline door mode are absent. Error shape is `{message}` everywhere (`app.ts:64-72`), never the specced `{code, message, field?}`.

## 2. Implemented-but-unspecced (divergent surface)

- **`/offers/*`**, the "Set your price" feature was built as `Offer`, not `PriceWatch`: no saved payment method, no auto-purchase, tier matched by name string.
- **`POST /orders/intent`**, replaces the spec's holds→quote→orders trio; bakes Stripe PaymentIntent creation into the reservation step.
- **`POST /tickets/:code/transfer`**, immediate email transfer, replaces pending/claim model.
- **`POST /tickets/:code/list`, `GET /tickets/sellable`, `GET /listings`, `/listings/mine`**, resale built per-ticket-code rather than the Listing entity with `ticket_ids[]`/`split_rule`.
- **Referral system** · `referralCode`/`referredByCode`/`referralCount` on User (`db.ts:99-101`), `REFERRAL#` items, `/account/referrals*` (`account.ts:423-464`). Nowhere in spec.
- **`/faqs`** static endpoint (`account.ts:466`), **`/health`**, **`GET /auth/me`**, **`/auth/refresh`**, **`/auth/logout`**, **`/auth/verify-email/*`**, reasonable additions, unspecced.
- **Stripe Connect Express** for fan payouts (`account.ts:200-267`), spec says "saved bank account"; Connect is a defensible choice but changes the withdraw UX (hosted onboarding) and should be confirmed.
- **Promo scope `TIER`/`tierId`/`startsAt`**, richer than spec's event-or-all scoping.

## 4. Rule coverage A1, Y3

**Accounts**
- **A1** Partial, 8+ char signup password ✓ (`auth.ts:69`); email unique case-insensitive ✓ (`db.ts:47,282`); **password-change number requirement missing** (`auth.ts:264`)
- **A2** Partial · `role:"user"|"creator"` ≈ intent (`auth.ts:70`), but no `next` routing hint
- **A3** Contradicts, no `interests_min_3` (maxItems only); **WELCOME10 is seeded as a creator-owned promo** (`seed.ts:194-204`), never granted per-user on onboarding
- **A4** Missing, no memberships/last_mode; login returns no `landing`
- **A5** Missing, no profile switching exists
- **A6** **Contradicts** · `deleteUser` (`db.ts:2127`) has zero blocking checks; it deletes then cleans up listings/offers, and leaves upcoming tickets/live earnings untouched
- **A7** Partial · `revokeAllRefreshTokens` (`auth.ts:279`) kills *all* sessions incl. current; spec says other sessions only

**Orgs & team · O1, O4, T1, T4: all Missing** (no Organisation/Membership). T1's per-org roles are approximated globally by `User.role`, model-level contradiction.

**Events**
- **E1** Divergent, different enum (`db.ts:145`); `scheduled/on_sale/sold_out/live/ended/settled/postponed` all absent; `CANCELLED`/`COMPLETED` unreachable
- **E2** Missing, no venue capacity; `setVenueLayout` (`db.ts:1867`) only guards against shrinking below sold+reserved (`db.ts:1906-1910`)
- **E3** Missing/Partial, no event-edit endpoint for date/venue (moot); section removal is blocked if sold/reserved (`db.ts:1933-1942`), closest analog; tier deletion impossible
- **E4** Missing, no reminders

**Buying**
- **B1** **Contradicts**, spec max **6**/order; schema allows `maximum: 8` (`orders.ts:53`); offers allow 8 (`db.ts:1311`)
- **B2** Implemented, atomic `available >= :qty` condition (`db.ts:758-763`)
- **B3** Implemented, reservation at intent + sweeper (`sweeper.ts`); the "no charge on sold-out" outcome holds via PI-not-yet-paid release
- **B4** Implemented · `claimListingForCheckout` ACTIVE→CHECKOUT, 409 "just sold" (`db.ts:1706-1723`, `orders.ts:158-160`)

**Pricing & payments**
- **P1** **Contradicts** · `platformFeePercent` defaults to **12** (`env.ts:54`), spec says 5%
- **P2** **Contradicts**, fee computed on `subtotal − discount` (`orders.ts:338-341`), so the fee *is* reduced by promos; spec: discount applies to subtotal only, never the fee (fee should be on full subtotal)
- **P3** Partial, check order is `active → maxUses → starts → ends → scope → tier → per-user` (`orders.ts:292-325`) vs spec `exists → not-used-by-user → event → resale → expiry → max_uses`; per-user check runs last and only scans PAID orders; `first_order_only` absent
- **P4** **Missing**, no client `Idempotency-Key`; each retry mints a new order + PI
- **P5** Implemented · `usedCount` incremented inside `fulfillOrder`'s transaction (`db.ts:1156-1164`). **Bug: also incremented again in the webhook** (`orders.ts:422-425`) → promo uses are double-counted
- **P6** Partial, order currency = event currency (`orders.ts:233,352`); **no tax anywhere** (no `tax_minor` field)

**Tickets & transfer**
- **X1** Partial, email only, existing account required; self-transfer rejected ✓ (`db.ts:1239`); no phone targets, no partial-qty semantics (each ticket transferred individually ✓)
- **X2** **Contradicts** · "The ticket code stays the same" (`db.ts:1221-1223`); ownership moves but **the sender's QR keeps working** · R1/decision-1 violation, enables screenshot fraud (scenario 1)
- **X3** Partial, listed tickets blocked from transfer (`db.ts:1233-1236`) and scanning flips VALID→USED regardless of listing (a listed VALID ticket can still be scanned by seller, no `listed` ticket status); transfer-pending doesn't exist
- **X4** Missing, no doors-open cutoff (no `doors_at`)

**Resale**

- **R2** **Missing** · `createListing` (`db.ts:1610-1659`) performs no cap check; no `face_minor` on tickets to cap against
- **R3** **Contradicts**, earnings credit `listing.priceCents` in full (`account.ts:39`); no 5% seller fee anywhere
- **R4** Missing, no royalty, no ledger
- **R5** Implemented, buyer pays `price + fee%` on resale (`orders.ts:163`), but at the 12% default (P1)
- **R6** Partial, pending/ready split on `eventStartsAt` (`account.ts:34-35`) rather than event end; works approximately
- **R7** Contradicts, listings sorted by createdAt desc not price (`db.ts:64-65,1663-1681`); not nested under tiers; own listings returned to the seller (blocked only at purchase)
- **R8** Missing · `promoCode` is silently ignored on the resale path (`orders.ts:146-181` never reads it)
